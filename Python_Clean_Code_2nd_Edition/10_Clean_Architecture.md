## 1. 좋은 아키텍처의 특징

좋은 아키텍처의 특징은 다음과 같다.

* 품질 속성 (확장성, 보안성, 고성능, 내구성 등)
* 즉, 다음과 같은 특징을 말한다.
  * 시스템 붕괴/오류 없이 **많은 요청/부하 처리 가능**
  * **특별한 유지보수 없이** 오랫동안 작동 가능
  * 새로운 요구 사항에 대한 **확장성**

중요한 것은, **실용성이 이상보다 우선** 이라는 것이다.

## 2. 관심사의 분리

**컴포넌트를 작게 유지하고, 함수는 한 가지 작업만 하도록** 해야 하는 이유는 다음과 같다.

* 작은 함수는 **이해, 디버깅, 테스트 등이 쉬움**
* 단위 테스트 작성이 쉬움

## 3. 추상화 관련

* 코드의 표현력은 **그 자체로 문서화가 되는 수준** 이어야 한다.
* 소프트웨어 아키텍처는 **그 자체로 시스템의 구성, 동작 등을 설명** 할 수 있어야 한다.

## 4. 소프트웨어 컴포넌트

대규모 시스템의 경우, **소프트웨어가 어떤 컴포넌트로 구성되어 있는지** 를 먼저 파악해야 한다.

* 의존성 관련
  * **베이스라인 (Baseline)** 은 전체 패키지의 목록 및 배포된 버전을 말한다.
  * **도커 (docker)** 는 동일한 코드 재 실행 시의 동일한 결과 재현을 보장하지는 않는다.
  * 항상 Dockerfile 에 의존성을 설치해야 한다. (```requirements.txt``` 를 이용)

## 5. 추상화 관련

추상화에서 중요한 것은 **기술적 요구사항을 최대한 숨기는** 것이다.

## 6. 의도 공개

**의도 공개 (intention revealing)** 는 다음과 같은 개념을 의미하며, **매우 중요하다.**

* 코드에서 사용되는 모든 이름은 **그 함수 등이 무엇을 하는지 명확히 표현** 되어야 한다.
* 함수는 **관심사가 분리, 의존성이 격리** 된 상태로 유지되어야 한다.
