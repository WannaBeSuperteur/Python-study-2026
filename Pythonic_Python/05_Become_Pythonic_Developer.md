## 1. 파이썬 표준 라이브러리 활용

* Python에서 표준 라이브러리는 **신뢰 가능한 내장 도구를, 바퀴를 추가하지 않고** 사용한다는 이점을 갖는다.

| 표준 라이브러리                        | 설명                                                                                                                        | 특이 사항                                          |
|---------------------------------|---------------------------------------------------------------------------------------------------------------------------|------------------------------------------------|
| ```pathlib```                   | ```Path``` 객체를 이용하여 파일과 폴더를 **객체 지향적으로 다룸**<br>- 문자열 더하기에 의한 가독성 저하 해결<br>- OS 별 경로 구분자 차이로 인한 버그 해결                      | ```/``` 로 경로 합치기 가능                            |
| ```collections```               | - ```Counter``` 로 빈도수 계산<br>- ```defaultdict``` 로 리스트 자동 초기화<br>- ```deque(maxlen=n)``` 으로 최근 항목 유지 (슬라이딩 윈도우 개념)         |                                                |
| ```itertools```                 | **반복문 조립** 을 위한 라이브러리<br>- ```pairwise``` 로 연속한 두 값 비교<br>- ```accumulate``` 로 누적합 계산<br>- ```combinations``` 로 가능한 조합 생성 |                                                |
| ```functools```                 | 재사용성이 좋은 함수에 대한 **추가 기능** 제공<br>- ```partial``` 을 통해 **인자를 일부 고정한 프리셋 함수** 생성 가능                                          | ```lru_cache``` 함수로 **함수 결과 캐시 - 속도 크게 향상 가능** |
| ```datetime``` + ```zoneinfo``` | **서로 다른 지역 간** 시간 계산을 안전하게 함<br>- ```timezone.utc``` 를 통해 UTC 기준 시각 계산 가능                                                 |                                                |
| ```statistics```                | 기본 통계 함수 모음<br>- ```mean``` (평균), ```median``` (중앙값), ```pstdev``` (표준편차) 함수 제공                                           | **외부 라이브러리 (NumPy 등) 없이** 통계 분석을 하는 함수 제공      |
| ```heapq```                     | **상위/하위 K개 값 추출** 시 활용<br>- ```nlargest(n, data)``` : 최댓값 N개 반환<br>- ```nsmallest(n, data)``` - 최솟값 N개 반환                 | 전체 데이터 정렬보다 빠른 방법 제공 **(큰 데이터셋에서 유용)**         | 
| ```re```                        | 정규 표현식 (패턴 매칭)                                                                                                            |                                                |

## 2. 파이썬 프로젝트 구조

* ```src/```, ```tests/``` 와 같이 **코드를 서로 분리하는** 구조가 많이 권장된다.
  * 그 이유는 **테스트 코드가 서비스 코드와 섞이는 것을 방지** 하는 등의 이점이 있기 때문이다.
  * ```pytest```, ```unittest``` 는 **```tests/``` 폴더를 자동 인식** 한다.
    * 그 안의 파일은 ```test_...py```, 함수명은 ```test_func_name``` 등으로 **앞에 ```test_``` 를 붙이면 자동 인식** 된다. 

| 구조           | 설명                                |
|--------------|-----------------------------------|
| ```src/```   | 실제 서비스의 **프로덕션 코드** (핵심 기능 코드 포함) |
| ```tests/``` | 코드가 잘 동작하는지 확인하는 **검증 코드**        |

* ⭐ **Python 프로젝트 환경설정은 ```pyproject.toml``` 로 하는 것이 매우 좋다.**
  * 이 파일은 **프로젝트 이름, 버전, 필요 패키지, 빌드 방식 등을 한 곳에 모아서 정의** 한다.
  * 이 파일이 **매우 중요** 한 이유는 다음과 같다.
    * 팀원 간 환경 차이 최소화 (코드 실행 일관성 유지)
    * CI/CD 등 자동화 시 필요한 정보 제공
    * PyPI 등에 배포 (업로드) 시 필수

## 3. 문서화 전략

**Pythonic 한 문서화 전략** 은 다음과 같다.

* 공개 API 함수 (사용자가 직접 사용) 에는 **반드시 docstring** 을 넣는다.
* 한 줄 요약 + ```Args``` ```Returns``` ```Raises``` ```Examples``` 형식을 유지한다.
* type은 **시그니처 부분에만 넣고 docstring 에는 넣지 않는다.**
  * 예: ```def func(x: int, y: int, name: str) -> str:```
* 패키지/모듈 최상단 docstring을 통해 **개요를 제공** 한다.

## 4. 코드 리뷰 (협업) 관련

* Pull Request 원칙
  * 하나의 PR은 **300 line 이내** 를 원칙으로 한다.
  * 커밋 단위로 **변경의 논리** 를 나타낸다.
  * 승인 조건은 **테스트 통과 + 자동 점검 통과 + 체크리스트 통과** 여야 한다. **(자동 점검 필수)**
* Pull Request 리뷰 태도
  * 사람을 공격하는 대신, **코드를 개선하려는 태도**
* 커밋 메시지는 **무엇을 왜 바꿨는지** 남긴다. (명확한 커밋 코멘트)
